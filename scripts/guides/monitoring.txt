@@ 3 Cross-check loss without double counting
Corroborate the observed loss with an independent measurement.

Start in WSL:
  make traffic-diagnostics
@@ hint

the subinterface discard row in show interface detail. Check deltas and resets.

@@ investigation
Keep the offered load fixed. In Telemetry Health inspect Capacity queue collection
and Linux queue drops (last 5 min) for Lagoon Transit.

  make enter NODE=edge01.bob1.lagoontransit.test
Inside the Lagoon router:
  info from state interface ethernet-1/1 statistics
  quit
WSL repository:
  make traffic-10mbit

Inspect: counter deltas between the two displayed samples and the receiver's loss,
not only an absolute cumulative counter. Match interface, direction and time window.
Decision: consistent sending-queue drops and receiver loss corroborate congestion.
A missing queue sample, reset counter or failed collection invalidates a numeric
comparison. After reducing to 10 Mbit/s, check whether NEW drops stop accumulating.
Note the counter deltas and receiver loss.
@@ solution
The netem queue and SR Linux counter can report the same loss, so do not add them.
At 10 Mbit/s, new congestion drops stop. Rolling-window graphs retain old samples
until they age out. Queue and router samples may differ because they are sampled
separately.

@@ 6 Compare a short burst with the dashboard's rate window
Can Grafana show a five-second burst? Compare short and long rate windows.

Start in WSL:
  make traffic-stop
For a clean burst, ensure there has been no generated traffic for five minutes.
Use that interval to review your earlier graphs if needed. Then run:
  make traffic-burst-40mbit
The burst stops automatically. Keep previous faults cleared.
@@ hint
In WSL:
  make traffic-status
In Grafana Explore, select Prometheus and switch to Code. Use Add query for
the second expression, also in Code mode. Both queries return Mbit/s:
  rate(reefnet_interface_out_octets_total{source="edge01.bob1.lagoontransit.test",interface_name="ethernet-1/1"}[10s]) * 8 / 1e6
  rate(reefnet_interface_out_octets_total{source="edge01.bob1.lagoontransit.test",interface_name="ethernet-1/1"}[5m]) * 8 / 1e6
Show both over the same time range containing the burst. Changing the dashboard
time range alone does not change the rate window. What happens to the peak height?
Check the receiver in WSL:

Inside the service node:
  tail -n 15 /tmp/iperf-server.log
Use exit to return. Scrape timing can affect the visible peak.
