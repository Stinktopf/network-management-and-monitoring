Inspect: instance policy, peer-to-group mapping, group overrides, referenced
prefix matches and actions. Compare that configuration with the observed route trace.
Decision: if the route exists locally but is not advertised, identify the effective
export rule. If it is advertised or absent locally, investigate that different
boundary first. An API error or empty snapshot is not evidence of an absent override.
Keep the raw snapshot. Do not generate a write from an unverified or stale assumption.
@@ solution
Edge 01 has the customer route, but its Lagoon advertisement lacks the prefix and
Lagoon has no matching forwarding entry. The snapshot shows:
  instance export-policy: EXPORT-BGP
  peer 192.0.2.2: peer-group lagoon-v4
  group export-policy: BLOCK-CUSTOMER-V4
  policy: CUSTOMER-V4 / 198.51.100.0/24 exact -> reject
The leaf to remove is:
  /network-instance[name=default]/protocols/bgp/group[group-name=lagoon-v4]/export-policy
Deleting this group override restores instance inheritance. Replacing the entire
BGP subtree or editing a shared policy would exceed the evidence-based scope.

@@ solution
Preconditions: target and incident match steps 1-2, instance policy is EXPORT-BGP,
and the re-read group still carries BLOCK-CUSTOMER-V4. On this single-operator lab,

  exit
